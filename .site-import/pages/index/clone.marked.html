01

What one scenario goes through

Six stages, in order, for every scenario. Each is stored, so a report shows which one decided the verdict.

  1. 01

    Scenario sent

    A fixed input from a versioned suite — ordinary, tricky or an attack — over its declared channel.

  2. 02

    Reply recorded

    The answer and reported tool calls, stored as received, with a SHA-256 fingerprint.

  3. 03

    Rules checked

    Deterministic checks first. They can fail a scenario, never pass one.

  4. 04

    Effect read back

    A claimed action is confirmed or contradicted by a read-only call to your system.

  5. 05

    Graders vote

    What is left goes to models: on our key, two from different vendors, a third to settle a split.

  6. 06

    Evidence sealed

    Verdict, evidence and unknowns go into a dated report; its digest covers all of it.

02

Manual spot-checking covers a fraction of what your agent does

A prompt changed on Tuesday and the client noticed first. “We think so” is not an answer to “is it still behaving?”

What teams usually have

  • A screenshot from Tuesday
  • “Seems fine” in a chat thread
  • Ten prompts tried by hand
  • The policy in one person's head
  • No record of what failed last month
  • “The agent said it refunded it”

Nothing here can be handed to a client, compared with last month, or shown to an auditor.

→

What Novera produces

  • ✓

    Forty-nine scenarios, every time

    Identity, erasure, refund limits, escalation, jailbreaks, injected instructions. A suite version never changes, so reports compare.

  • ✓

    Stored evidence for every verdict

    Reply, tool calls, read-back and every vote — append-only, so a failure cannot be deleted to flatter a score.

  • ✓

    Unknowns named, not hidden

    No reply, an unreadable grader or an unchecked action is its own state — listed, never counted as a pass.

  • ✓

    A sealed report with a revocable link

    Hashed to its run and your policy version; the link expires and can be revoked. No policy text, keys or raw transcript.

03

A report is only worth sending if it cannot be quietly improved

Enforced in the database, not promised in a brochure. Try each one: the data is illustrative, the behaviour is the product's.

01

A policy is versioned, never edited

Saving a change creates a new version. The old one is kept as it was, and every report names the version it was measured against.

02

A verdict is two vendors agreeing

On our key, two models from different vendors grade each scenario. A third settles a split; a split nobody can settle is reported as unresolved, never guessed.

  2. Vendor B: fail

03

A claimed action is checked, not believed

When the agent says it acted, a read-only call to your system of record confirms or contradicts it — and a contradiction is settled without asking a model.

05

No result is never a pass

A timeout, an unreadable grader or an action nobody could check produces no verdict. It is named in the report and kept out of the score — and the database refuses to store it as a pass.

06

Fits the way you already ship

Gate a release, rerun on a schedule, or start a run from n8n. A missing verdict fails the gate like a failed one.

  • Release gate — A REST call starts a run; five exit codes tell a pass from a failure from missing evidence.

  • Schedules — A pinned suite at a fixed UTC time; a schedule that cannot start pauses and says why.

  • n8n and webhooks — Signed webhooks and four importable n8n workflows, each run in n8n before it shipped.

  • Production failures — Send a real failure in; it comes back as a draft scenario a person approves.

release-gate.sh · a sketch; the full script is in the docs
auth="Authorization: Bearer $NOVERA_KEY"
run=$(curl -fsS -X POST "$api/runs" -H "$auth" \
  -H "Idempotency-Key: $GITHUB_SHA" -H 'content-type: application/json' \
  -d '{"agent_id":"…","suite_id":"…"}' | jq -r .run.id)

# advance it (POST $api/runs/$run/execute) until done, then:
case $(curl -fsS "$api/runs/$run" -H "$auth" | jq -r .run.outcome) in
  pass) exit 0 ;;
  fail) exit 1 ;;   # a scenario failed
  *)    exit 2 ;;   # missing evidence stops the release too
esac

07

Where your data goes, and what a report does not say

The limits, before you find them. Each is also in every report's limitations block.

  1. Your agent

    Your infrastructure

    • An endpoint you own or are authorised to test
    • That authorisation is recorded with every run
    ⇄scenarios out, replies back

  2. Novera

    Database in Frankfurt (EU)

    • Stores verdicts, evidence, policy versions and reports
    • Model keys encrypted, decrypted only on the server
    • Raw replies emptied after your retention period; the verdict and a fingerprint stay
    ⇄replies out to be graded

  3. Grading providers

    May be outside the EU

    • Receive the agent's replies to grade them
    • Each gets only the data its published terms allow; personal data becomes placeholders where needed
    • Every report names the models that graded it

Database residency and model processing are two different questions. What goes where, exactly.

Recorded

Observed by Novera during the run

  • Each reply and the tool calls the agent reported
  • Read-back results: confirmed, contradicted, unavailable
  • Every grader's vote and how it was settled
  • Timings, timeouts and errors

Declared

Stated by you, and labelled as yours

  • The policy text, frozen per version
  • That you are authorised to test the agent
  • A release or knowledge-base revision, if you give one
  • Whether the agent is production

Not verified

Outside what a run can show

  • Any action no read-back covered
  • Behaviour on conversations outside the suite
  • Which legal obligations apply to you
  • Anything after the report's date

What Novera is not

A document that overstates itself is worth less — especially to the person you hand it to.

  • Not a certification. Novera is evidence of testing.

  • Not legal advice. It does not say which obligations apply to your organisation.

  • One dated run. One suite version against one policy version.

  • Only the suite. Not your agent's behaviour on every conversation, nor anything outside it.
